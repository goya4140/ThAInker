# ThAInker GitHub Pages

公开地址：<https://goya4140.github.io/ThAInker/>。

## 两个展示入口

- 仓库首页 `README.md`：品牌主视觉、五阶段流程图、人工介入表、可展开的逐屏截图和运行入口。
- `site/`：无构建依赖的静态前端。支持五模块浏览、章节和表格切换、本地参考图预览、人工选题、方法审批、暂停继续、模拟故障恢复及预生成样例下载。

站点只在浏览器内维护本次演示状态，刷新会重新开始。不会调用 Python API、模型、GPU、训练服务或 LaTeX 编译器，也不会把任何文件上传到服务器。参考图本地预览使用浏览器 Object URL。

## 人工节点

| 节点 | 实际系统语义 | 静态导览 |
| --- | --- | --- |
| Search 选题 | 可选，自动 / 人工两种方式 | 开始前可勾选人工选题 |
| Design 方法修改 | 只有方法修改触发时，必须批准指定 Revision ID | 可勾选模拟提案；批准、拒绝、结束 Idea 均可体验 |
| Writing 材料与模板 | 可选补充材料、替换模板、逐步或自动推进 | 展示输入边界、六章节与模板示意；不上传实验文档 |
| Table 反馈 | 可选输入配置和修订要求 | 可切换示例表口径，确认仅浏览器内的模拟反馈 |
| Figure 三张参考 | 实际生成前必须由作者确认 | 导览停在确认节点；支持本地图片预览，不进行绘图 |
| 跨阶段暂停恢复 | 沿原任务和安全边界继续 | 暂停恢复原等待状态，不绕过审批 |

研究内容、评审、评分、结果和状态全部明确标为模拟。真实系统的能力说明与本次静态交互分开表述；预生成样例不会因本次浏览器点击而变化。

## 本地预览

在仓库根目录运行：

```bash
python3 -m http.server 8780 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8780/site/>。使用子路径预览，以便发现 Pages 仓库前缀相关问题。所有站内脚本、媒体和下载地址均使用相对路径。

## 部署

仓库 Settings → Pages 使用 GitHub Actions。工作流 `.github/workflows/pages.yml` 在 `main` 上的 `site/**` 或工作流变化后执行，也支持手动触发：

1. 检查静态状态机和 JavaScript 语法。
2. 配置 GitHub Pages。
3. 仅上传 `site/` 作为 Pages artifact。
4. 发布到 `github-pages` environment。

不上传仓库根目录，不包含 `assets/`、虚拟环境、Codex 凭据或本地日志。仓库代码发布到 `main` 后可在 Actions 中查看部署结果。

## 维护公开样例

`site/downloads/` 中仅保留经过筛选的模拟 PDF、PPTX、CSV 和源码 ZIP；每个包内包含模拟说明。不要直接复制内部 `deliverables.zip`、任务 manifest、日志、凭据或带本机绝对路径的 JSON。

`site/media/` 包含品牌 SVG、静态演示截图、模板主图预览和项目已有默认参考图。截图内容来自模拟案例；README 的逐屏截图应与相应模块视图同步更新。

验证：

```bash
node --test site/tests/flow.test.mjs
node --check site/app.mjs
```

状态机用例覆盖人工选题、匹配提案批准、拒绝后恢复、参考图确认、故障恢复、结束 Idea 与不可变转换。发布前还应实际点击一次完整导览，检查移动布局、下载和控制台错误。
